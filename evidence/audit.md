## The hit is textual, not nominal

Our patch keeps `LRUCache.__touch()` and replaces its body. Upstream
`c128aa5` does the opposite: it inlines the same five lines into
`__setitem__()` and deletes `__touch()` entirely. Function-name search,
file search and commit-message search all miss it; the added-line set
matches 5/5.

Two commits carry the identical change:

```
598aaede07ea  dev/v7.3.x   2026-11-15  Improve LRUCache.__setitem__() performance.
c128aa5e538b  master       2026-11-15  Improve LRUCache.__setitem__() performance.
patch-id (both): 19324221d52295596531a861bdd84300178adc7e
```

The audit reports `598aaed` because both commits share a timestamp; either is
the same patch. `--all` is required: a clone that only fetched the maintenance
branch (or only the default branch, before the fix was merged) would see one of
them, not both.

## One clear row is not a clean negative for the right reason

`markdown-opt-lab` has 10 of 41 added lines present at HEAD, yet zero history
candidates. `git log -S` only fires when the *number of occurrences* of a line
changes; lines moved inside the file keep their count and are invisible. So
this row is "no body introduced in the window", not "the body is definitely
new". It is reported as `clear` (bounded negative) and not as `inconclusive`.
